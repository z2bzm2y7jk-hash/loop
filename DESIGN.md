# Loop design
Mode: Operate. The user delegated visual decisions in the detailed brief.
Direction: clubhouse scorebook. Warm off-white paper, forest green actions, quiet olive secondary elements, editorial serif headings and compact sans-serif labels. Persistent desktop rail becomes a five-action mobile bottom bar with an emphasized Play action. Home has an asymmetric invitation and season summary; live scoring prioritizes four large score controls over decoration.
Candidates considered: printed scorecard, course wayfinding, golf editorial, clubhouse scorebook, tournament pairing sheet, yardage book, pro-shop receipt. The assigned fourth direction informed the implementation. The concept service was unavailable; the direction used the supplied product brief without external challengers.
Tokens use three layers. Primitives define forest, sage, cream, clay, white and lime. Semantic aliases define canvas, raised and soft surfaces, strong and muted text, borders, actions, focus and status colors. Component tokens define the 44px control minimum, control and card radii, raised shadow and mobile navigation height. Border-separated lists remain the primary structure; cards use 12–14px radii and dialogs use 16–17px corners. No remote imagery or font services. Georgia and Arial use local system fonts; the app still requires a running Next.js server and does not provide an offline service worker.
Responsive behavior: the rail narrows at 1100px and becomes bottom navigation at 760px. Scoring uses a horizontal player strip; additional players scroll into view. Rules and simulation dialogs become bottom sheets on mobile. Scorecards scroll horizontally with sticky player names.

Mobile quality floor: phone layouts support 320px through 760px without page-level horizontal overflow. Every interactive control is at least 44×44px, form fields use 16px text to avoid iOS zoom, top and bottom chrome honor safe areas, and primary navigation exposes an active state to both sighted users and assistive technology. At 360px and below, score cards become a deliberately scrollable strip that leaves the next player partially visible as a swipe cue. Supporting text stays at 10px or larger and measured WCAG 2.1 AA contrast is required on light and tinted surfaces.
Interaction styling: green focus outlines, lime text selection, green input carets, tabular score numerals, subdued disabled controls, and offset soft shadows on dialogs and toast messages. A desktop hero entrance uses a short upward motion and fade; reduced-motion preferences disable animation and transitions.

Feature extension: selected game cards now lead to explicit whole-dollar settings, using bordered disclosure rows. This keeps multiple game options scannable. In-play decisions live below the score controls, with a small jump target near the hole heading. Wolf choices are pill-shaped large tap targets; Hammer offers show the current team stake and response options; Games status records the outcome by hole. Existing score entry and color hierarchy remain the visual priority.

Weekly group flow: a saved group is a durable roster of up to 24 golfers, while each weekly event requires 4–12 attendees and automatically creates balanced playing groups of 2–4. “This week” is the group’s first view and prioritizes the newest unfinished event, falling back to the latest completed event. Planning defaults to the group’s saved home course and House Rule; a newly planned event saves those choices for the next week. Playing groups use stacked cards on phones, with the primary scoring action kept inside each card. Before scoring starts, swapping is a two-tap interaction: select one golfer, then a golfer in another group; the first selection receives a persistent highlighted state, and shuffle remains a secondary action. Once a playing group starts, lineup editing stops. Each completed playing-group round links back to the event, exposes its result from the event card, and contributes to a single “Combined money” standing with visible saved-round progress.

Shared weekly events preserve that hierarchy on every phone. Sharing uses one focused permission choice—follow only or help organize and score—before exposing the system share sheet or copy action. The live event page leads with date, course and access level; each playing-group card shows a plain-language state and one contextual action: wait, set up, open live scoring or view results. A golfer claims their roster identity once, already-claimed names become unavailable, and organizer-only lineup controls stay visible only while they can act. Recent activity identifies editors without competing with the playing groups, while viewers receive a quiet auto-update message instead of editable-looking controls.

Weekly links remain under the captain’s control. A subdued stop-sharing action opens an inline confirmation that explains the effect before revoking access. Stopping a link preserves the event, scorecards and audit history; the captain can create a fresh link with new permissions at any time.

Help is a first-class phone flow rather than a reference manual. A visible Home card opens seven native disclosure sections with literal, task-based steps, 16px instructional text on phones and 44px-or-larger tap targets. It teaches round setup, scoring, weekly links, bets, corrections, exports and Home Screen installation. The first section opens by default, a reassurance note explains exactly when scores are saved, and quick actions take the golfer directly into the related task. Help remains available from Profile, the desktop rail and the shared weekly-event header so invited golfers can find it without learning the main navigation first.
